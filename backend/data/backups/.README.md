# `backend/data/backups/`

Daily snapshots of `backend/data/store.json`, created automatically by
`scripts/daily-backup-store.ps1` running on Windows Task Scheduler.

## Naming

| Pattern | Source | Retention |
|---|---|---|
| `store-YYYYMMDD-HHmmss.json` | daily-backup-store.ps1 (Task Scheduler) | 30 days, then auto-purged |
| `store.PRE-PWRESET-MOTI-*.json` | scripts/moti-pwreset.js (manual password reset) | kept forever (small, audit value) |
| `store.PRE-RECOVERY-STUCK-QC-*.json` | scripts/recovery-stuck-qc-waves.js (manual recovery) | kept forever |
| `store.PRE-RESTORE-*.json` | scripts/restore-store-from-backup.ps1 (auto-saved before a restore) | kept forever |
| `store-*.CORRUPT` | renamed by daily-backup if JSON validation failed post-copy | kept until manually deleted (forensics) |

## How to restore

1. List backups (most recent first):
   ```
   ls backend/data/backups/ | Sort-Object -Descending
   ```
2. Pick the one just before the bad state.
3. Run from the repo root:
   ```
   powershell -ExecutionPolicy Bypass -File scripts/restore-store-from-backup.ps1 <BACKUP_NAME.json>
   ```
4. The script will:
   - validate the backup is parseable JSON
   - save the current state as `store.PRE-RESTORE-<timestamp>.json` (so the restore is reversible)
   - stop PM2 `sap-logistics`
   - copy the backup over `store.json`
   - start PM2 back up
   - wait for HTTP 401 on `/api/auth/me` (liveness check)

## How to verify a backup is good

```
node -e "JSON.parse(require('fs').readFileSync('backend/data/backups/store-YYYYMMDD-HHmmss.json','utf8')); console.log('OK')"
```

If it prints `OK`, the backup is at least syntactically valid JSON. (It
does not guarantee the data inside is consistent — that's why we keep
many days of history.)

## When to manually clean up

`store-*` files get auto-purged after 30 days. Everything else is kept
forever. If `data/backups/` gets larger than ~500 MB, scan for old
`store.PRE-*` files from defunct operations and decide which ones can go.

## When NOT to delete

- **Anything from the last 30 days** — too fresh, might still be needed.
- **`store.PRE-RESTORE-*`** — these are your *current* state before a
  restore. Critical if the restore turned out to be wrong.
- **`*.CORRUPT`** — kept for diagnosis. If the daily backup ever creates
  one of these, investigate WHY before deleting.
